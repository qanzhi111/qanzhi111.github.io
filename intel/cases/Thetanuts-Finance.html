攻击方法论

标准攻击流程（AI辅助废弃合约猎杀）


第一步：批量发现目标
  工具: Etherscan/BscScan API
  筛选条件:
    - 部署时间: 2021-2023年
    - 仍有ETH或代币余额
    - 最后交易时间 > 6个月
    - Verified = False（未验证合约优先）

第二步：字节码反编译
  工具: Dedaub、Heimdall、Etherscan Bytecode-to-Opcode
  能力: 批量扫描数千个未验证合约，自动发现漏洞模式

第三步：漏洞验证
  工具: 交易模拟、fork测试
  确认: 漏洞可利用 + 资产可提取

第四步：执行攻击
  成本: 一笔Gas费
  速度: 秒级完成

共同漏洞模式

  1. 合约已废弃但链上残留资产 — 没人能暂停或修复
  2. 旧的验证逻辑在废弃后变得可绕过 — 安全假设过时
  3. 无管理员密钥 — 无法紧急响应
  4. 不可变合约 — "不可变=安全"的假设被证伪

技术分析

为什么"不可变≠安全"

开发者的传统思维：


不可变合约 = 没人能修改 = 安全

现实：


不可变合约 + 没有管理员 + 停止维护 = 
  合约有数百万资产 + 没人能暂停 + 没人能修复 = 攻击者的提款机

为什么废弃合约特别危险

  1. 无人监控: 团队注意力转向新产品，旧合约告警规则被弱化
  2. 维护人员变动: 了解旧合约的人已离职
  3. 历史假设过时: 2021年的安全假设在2026年已不成立
  4. 权限路径被遗忘: 旧的控制路径重新变得可用而无人知晓

防御建议

对协议方

  1. 建立合约退役流程:
  • 资金迁移完毕后，确保合约余额为0
  • 撤销所有外部授权和权限
  • 在合约上标记为deprecated（即使不可变）
  • 通知用户移除对该合约的交互
  1. 定期审计残留资产:
  • 扫描所有历史部署的合约
  • 检查是否仍有TVL
  • 评估是否有可提取路径
  1. 设置监控覆盖:
  • 不要只监控活跃合约
  • 对已废弃合约保持基础监控

对用户

  1. 检查是否仍与已废弃合约有交互授权
  2. 定期撤销不必要的ERC-20 approve
  3. 如果持有的结构化产品在废弃合约中，考虑迁移

系统性风险评估

潜在目标范围

根据Chainalysis和ZeroDrift的分析框架，以下类型的合约属于高风险：

  • 部署于2021-2023年
  • 未验证源码（Verified = False）
  • 仍有资产余额（ETH/ERC-20）
  • 最后交易超过6个月
  • 无管理员/暂停功能

保守估计，以太坊上满足以上条件的合约数量在数千个级别。
