二、核心发现：废弃≠安全

2.1 问题本质

这些事件的共同特征是：项目方认为已弃用的合约，实际上仍保留完整的经济价值和操作权限。


废弃合约 = 仍部署在链上 + 仍有资金/授权 + 可执行交易 + 无人监控

2.2 DxSale案例详解（损失最大：$730万）

DxSale的旧版Locker合约原本用于长期锁定流动性，确保资金不会在约定期限前被取出。然而：

  • 随着团队注意力转向新产品，监控规则被弱化
  • 维护人员变动后，历史权限路径被遗忘
  • 一条旧的控制路径重新变得可用
  • 本应锁定的流动性被攻击者取走

2.3 TrustedVolumes案例（自动化攻击典型）

攻击者地址: 0xeEeEEe53033F7227d488ae83a27Bc9A9D5051756[^2]

被盗资产:

  • 1,291.16 WETH
  • 206,282 USDT
  • 16.939 WBTC
  • 1,268,771 USDC

漏洞: 自定义RFQ Swap Proxy合约漏洞（与2025年3月的1inch Fusion V1事件为同一操作者）

资金清洗:

  • 向Tornado Cash存入10.2枚ETH（约$2.36万）
  • 通过THORChain跨链转换为BTC（约$25万）

3.2 共同的根本原因

旧合约天然适合被自动化工具扫描：

  • 代码公开 ✓
  • 链上历史完整 ✓
  • 监控较弱 ✓
  • 往往保留过时的安全假设 ✓

3.3 AI放大效应

ZeroDrift指出：自动化分析正在降低系统性扫描废弃合约的成本。虽然目前没有公开证据表明AI参与了这五起攻击，但成本结构的变化值得关注——攻击者越来越容易系统性扫描"昨天的产品"。

四、攻击者TTPs（战术、技术和程序）

  1. 侦察阶段: 扫描Etherscan/区块浏览器，识别有资金残留的历史合约
  2. 代码审查: 分析遗留代码，寻找未修补的漏洞
  3. 权限路径识别: 查找被遗忘但仍有效的admin权限或授权
  4. 闪电贷放大: 使用闪电贷获取无限弹药
  5. 跨链洗钱: 通过THORChain、Tornado Cash等工具混淆资金

五、社区教训

5.1 对项目方

  • ❌ 合约不会因为团队停止维护就自动安全
  • ✓ 弃用合约应彻底下线，包括撤销所有授权权限
  • ✓ 建立合约生命周期管理流程

5.2 对用户

  • ❌ 不要以为协议停了，你的资产就安全了
  • ✓ 定期审查并撤销不必要的代币授权
  • ✓ 特别关注针对已弃用协议的授权

5.3 对审计机构

  • ✓ 扩展审计范围至"退役合约"
  • ✓ 开发自动化工具检测遗留授权
