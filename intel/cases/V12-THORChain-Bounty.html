V12 vs THORChain: Bounty Betrayal and the $10.7M Exploit That Followed

Executive Summary

Security startup V12 disclosed a critical fund-draining vulnerability in THORChain's GG20 threshold signature scheme (TSS) implementation to the protocol's bug bounty program. Weeks later, THORChain silently patched the flaw and told V12 the bounty was "Permanently Retired" — without paying. On May 15, 2026, an attacker exploited a near-identical vulnerability, draining $10.7 million from one of THORChain's five vaults. V12 has since announced plans to publish exploit code for additional vulnerabilities. This incident exposes systemic issues in DeFi bug bounty programs, responsible disclosure ethics, and the tension between protocol governance and security researcher rights.

Attack Vector Analysis

The Original Vulnerability (Disclosed by V12)

THORChain employs a Threshold Signature Scheme (TSS) based on the GG20 protocol, where multiple validator nodes must co-sign transactions to move funds. No single node operator holds the complete private key. V12 identified a critical flaw in this implementation that could allow fund extraction.

  • Vulnerability Type: GG20 TSS implementation weakness
  • Severity: Critical (fund-draining)
  • Discovery: V12 security research team
  • Disclosure: Submitted through THORChain's bug bounty program
  • THORChain's Response: Silently patched, then marked bounty as "Permanently Retired"

The May 15 Exploit

On May 15, 2026, a newly added validator node exploited the GG20 TSS vulnerability (or a near-identical flaw), draining approximately $10.7 million from one of THORChain's five vaults.

Attack Mechanics:

  • Attacker operated a newly added validator node
  • Exploited undisclosed cryptographic weaknesses in GG20 TSS
  • Soda Labs later confirmed it was a zero-day vulnerability
  • The exploit required human-level cryptographic reasoning (AI models reportedly could not replicate the attack)
  • Four other vaults remained unaffected
  • Automatic solvency checks detected the imbalance and halted signing within minutes

Key Transaction Details:

  • Loss: ~$10.7 million from a single vault
  • Detection: Automatic solvency monitoring within minutes
  • Response: Node operators halted trading, chain observation, and churning

Technical Analysis

GG20 TSS Vulnerability

THORChain's vault security depends on the GG20 threshold signature protocol, which requires multiple nodes to collaboratively sign transactions. The vulnerability identified by V12 and subsequently exploited relates to cryptographic weaknesses in this implementation.

Critical Details:

  • The vulnerability exists in the TSS library implementation, not in the GG20 protocol specification itself
  • A newly added node was able to exploit the weakness — raising questions about node admission vetting
  • The fix required patching the entire TSS library, suggesting a deep implementation-level flaw
  • Soda Labs confirmed the zero-day nature of the vulnerability

Controversial Response: Close-Source TSS Library

In a controversial decision, THORChain temporarily closed-sourced the TSS library during Soda Labs' security audit. Kenton, a THORChain team member, acknowledged this choice prioritized recovery speed over transparency. The library is expected to return to open-source status in future releases.

This decision undermines one of blockchain's core security principles: open auditability. Security researchers cannot verify that the patched TSS implementation is truly secure if the code is not publicly available.

The 11-Stage Restart Process (v3.19.0)

THORChain's recovery involves a complex restart sequence:

  1. Validators review and approve v3.19.0
  2. Compromised Vault Mimir setting activated (isolates drained vault)
  3. ADR-028 data migration validated
  4. Key share integrity verification (keyverify protocol)
  5. Signing unhalt
  6. Churn initiation (replace active validator set)
  7. Asset transfer to newly generated vaults
  8. Secured assets return
  9. Trade assets return
  10. Liquidity provider actions resume
  11. Full trading resumes

ADR-028 Loss Recovery Framework

  • Uses protocol-owned liquidity (POL) to absorb losses
  • Does NOT mint or sell new $RUNE
  • Avoids direct dilution for existing holders
  • Remaining shortfalls allocated across synthetic asset holders
  • Future system revenue rebuilds POL post-restart
  • A bounty window was activated for the attacker
  • The linked node was fully slashed

Analysis: The Bug Bounty Ethical Crisis

V12's Position

V12 followed responsible disclosure practices:

  1. Identified vulnerability
  2. Reported through official bug bounty channel
  3. Waited for response
  4. Received no bounty payment and was told the bounty was "retired"
  5. Watched the same vulnerability class get exploited for $10.7M
  6. Now plans to publish exploit code as leverage

THORChain's Position

THORChain's actions raise serious concerns:

  1. Silently patched without acknowledging V12's disclosure
  2. Retroactively "retired" the bounty (no payment)
  3. Closed-sourced the fix during audit (reduced transparency)
  4. Did not publicly credit V12 for the vulnerability discovery

Systemic Issues Exposed

  1. Bounty Program Credibility: If protocols can silently patch and retire bounties without payment, security researchers lose incentive for responsible disclosure
  2. Power Imbalance: Protocols control the terms; researchers bear the cost of discovery with no guaranteed compensation
  3. Transparency vs Speed: THORChain chose to close-source the TSS fix, prioritizing speed over community auditability
  4. Retaliation Risk: V12's threat to publish exploit code is a direct consequence of feeling exploited by the protocol

Implications for DeFi Security

  • Researcher Disincentive: If V12's experience becomes the norm, fewer researchers will report vulnerabilities through official channels
  • Exploit Code Publication: V12 publishing exploit code could enable copycat attacks on other protocols using similar TSS implementations
  • Regulatory Attention: Bug bounty program failures may attract regulatory scrutiny of DeFi governance practices
  • Insurance Gap: No clear framework exists for compensating researchers when protocols fail to honor bounty commitments

Lessons Learned

  1. Bug Bounty Programs Need Enforceable Commitments: Smart contract-based escrow for bounties could prevent retroactive retirement
  2. Responsible Disclosure Must Be Reciprocal: Protocols that accept vulnerability reports have an ethical obligation to compensate discoverers
  3. Open-Source During Fixes: Closing source code during security fixes undermines community trust and audit capability
  4. Node Admission Controls: The THORChain exploit was facilitated by a "newly added node" — vetting processes need hardening
  5. TSS Implementation Risks: Threshold signature schemes are only as strong as their specific implementation; protocol-level audits of TSS libraries are essential

Legal Implications

  • V12 may have legal grounds for breach of contract if THORChain's bug bounty program constituted a binding agreement
  • The silent patching before bounty retirement could constitute bad faith dealing
  • V12's planned publication of exploit code occupies a legal gray area (free speech vs. potential facilitation of future attacks)
  • THORChain's decision to slash the attacker's node bond demonstrates on-chain enforcement capability, but does not address the bounty dispute
