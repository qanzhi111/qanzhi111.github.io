Thetanuts Finance $2.1M Deprecated Vault Exploit 调查报告

调查日期: 2026-06-16

事件发生日期: 2026-06-15

来源: PeckShieldAlert, Blockaid, ExVul, Cryptopolitan, Crypto-Economy, CoinPost

严重程度: 🟠 中高 — 24小时内第二起deprecated contract攻击，"僵尸合约"模式确认

Executive Summary

2026年6月15日，去中心化期权协议 Thetanuts Finance 的一个已弃用（deprecated）vault遭受闪电贷攻击，损失约 $2.1M。攻击者利用 index-token 铸造/赎回逻辑中的整数除法截断漏洞，在 totalSupply 被消耗至接近0时触发舍入错误，实现零成本无限铸造。

约 $2M 的期权代币被白帽研究者回收，攻击者最终获利约 $139K（$105K USDC兑换为~60 ETH + $34K USDC期权代币）。

这是24小时内第二起针对已弃用 DeFi 合约的攻击——前一日（6/14）Aztec Connect 刚遭受 $2.19M "僵尸合约"攻击。两起事件共同确认了一个新兴系统性风险：攻击者正在系统性扫描区块链上已弃用但仍持有资产的智能合约。

Attack Vector Analysis

漏洞根因

据安全研究者 ExVul 的分析，漏洞存在于 legacy vault 的赎回数学逻辑中：

核心公式: depositAmount = backing * amount / totalSupply

当 vault 的 totalSupply 被 claim 操作消耗至接近 0 时，整数除法截断使 depositAmount 计算结果为 0。攻击者可以零成本铸造新代币，再用这些代币提取 vault 中的真实资产。

技术细节:

  1. Solidity 的整数除法在结果为小数时向下截断（floor division）
  2. 当 totalSupply → 0 时，backing * amount / totalSupply 的分母极小
  3. 但在 claim 先将 supply 耗尽的场景下，后续的 mint 操作中 amount 参数的特定值可使整个表达式结果为 0
  4. 攻击者利用闪电贷在同一交易内完成：推低supply → 零成本铸造 → 提取价值

攻击步骤


1. 闪电贷借入资金
2. 通过 claim 操作将 vault 的 totalSupply 消耗至接近 0
3. 触发整数除法截断 → depositAmount 计算结果为 0
4. 零成本铸造大量 index tokens
5. 使用铸造的 tokens 提取 vault 中的真实资产（USDC等）
6. 归还闪电贷
7. 将 $105K USDC 兑换为 ~60 ETH（打破链上可追踪性）

Case Background: Thetanuts Finance

Thetanuts Finance 是一个去中心化期权结构化产品协议，提供期权代币的铸造和交易。协议在迁移过程中将旧 vault 弃用，但未对弃用合约执行资产清理或自毁操作。

官方声明 (2026-06-15):

> "Our preliminary investigation indicates that this is once again, a deprecated vault that we have migrated from years ago. It has no relation with any of our current contracts or products. We will release a post-mortem once we get more details."

攻击模式特征

  1. 目标选择: 已弃用但链上仍存活、仍持有资产的合约
  2. 扫描方式: 可能通过自动化扫描所有含资产的 deprecated 合约
  3. 为什么现在爆发:
  • DeFi 安全工具（Blockaid、PeckShield）的实时监控使攻击窗口缩短
  • 攻击者转向竞争较少的"蓝海"目标——废弃合约无人监控
  • 数学类漏洞（整数截断、边界条件）在旧代码中普遍存在

与更广泛趋势的关联

  • Raydium AMM V3 ($1.34M, 2026-06-11): 同样是 legacy pool 被攻击
  • 6月 deprecated contract 攻击累计: $4.29M+（仅 Aztec + Thetanuts）
  • 行业模式: 弃用≠安全终结。合约永远在线，但无人维护

Lessons Learned

对协议开发者

  1. 弃用流程必须包含资产清理: 迁移 vault 后，旧合约中的资产必须全部提取或合约必须自毁
  2. 整数除法是经典陷阱: a * b / c 在 Solidity 中的截断行为需要在 supply 趋近0的边界条件下测试
  3. Deprecated 合约需要监控: 即使不再活跃，仍需要设置基本的异常交互告警

对用户

  1. 弃用协议中的资产≠安全资产: 旧 vault 可能无人维护、无人监控
  2. 及时迁移: 协议宣布迁移时，用户应及时将资产转移至新合约
  3. 白帽响应是关键防线: 本次事件中白帽回收了95%的资金

对 ChainSentinel 项目的启示

本次事件再次验证了独立监控层的必要性：

  • Deprecated vault 缺少内部监控 → 需要外部独立检测
  • Blockaid 在本次事件中发挥了关键作用（实时检测+攻击路径分析）
  • 可以开发 "deprecated contract scanner" 功能——扫描所有含资产的弃用合约并持续监控

Legal Implications

  • 攻击者利用数学漏洞而非私钥盗窃，在法律定性上更接近"未授权访问"
  • 白帽回收行为在法律灰色地带——未经授权的合约交互
  • Thetanuts 作为协议方未造成用户直接损失（当前产品未受影响），但遗留合约的资产归属存在争议
